# Attunetion review response worksheet

Apple rejected build 9 on October 5 under guidelines 4.3 and 4.2.6. If disputing the finding, Apple asked for a reply to the existing review message before resubmitting. This private worksheet is a draft. Replace the open publisher questions with verified answers before sending it.

[Original App Review correspondence](https://appstoreconnect.apple.com/apps/6757886472/distribution/reviewsubmissions/details/c5f49241-6a36-4c95-9260-1c410e39a7bc)

1. **What problem does the app solve?** Attunetion helps a person decide how they want to show up for a day, week or month and keep that intention visible. A reviewer can skip the introduction, write a daily intention, save it, then return to the current intention from the home screen. The writer can revisit earlier entries and choose a different focus for a longer period.
2. **Who uses it?** The product is designed for individuals who want a short personal reflection practice. It supports writing without an account and without enabling AI. This describes the intended audience. The publisher should add evidence about actual users if available.
3. **What meaningful gap does it fill?** The product combines time-scoped intentions, an editable writing guide, personal visual themes, a Home Screen widget and a short Watch entry flow. The reviewer can inspect each directly. Publisher input needed on the closest competing apps considered and which user need drove this design.
4. **What human testing changed it?** Automated onboarding and persistence tests ran across the supported platforms. Publisher input needed on human beta participants, how they used it, the feedback they gave and a concrete change resulting from that feedback. If there was no human beta, say so.
5. **Is it standalone or part of a suite?** The iOS, watchOS, macOS and visionOS experiences serve the same product, bundle family and private CloudKit container. Publisher input needed on comparable titles in the developer’s portfolio and the specific audience or workflow differences.
6. **Could another title incorporate this functionality?** The central workflow is writing and revisiting intentions across three time scales. Publisher input needed on which existing product Apple might see as overlapping and the practical reason to keep the experiences separate, or a plan to consolidate.
7. **What first-party code or assets are shared?** Targets in this app reuse the intention model and parts of the SwiftUI interface. The Watch companion has a compact entry experience and the iOS widget shows the current intention. Publisher input needed on code, visuals and assets reused across other published titles.
8. **Which third-party templates or libraries were used?** The release Xcode project has no resolved third-party Swift package dependencies. The backend uses the OpenAI SDK to implement optional suggestions. Publisher input needed on design templates, starter projects, purchased or generated assets and externally reused code, including material copied directly into the project.
9. **Who developed and owns the concept and branding?** The distribution account and project identify Nathan Fennel. Publisher confirmation needed on who originated the concept, owns the name and assets, commissioned the app if applicable, and is responsible for publication. An account name alone does not establish rights.
